BRIEF 29DESIGN PHASE

TEMPO

A flat, primary-colored geometric rhythm game where shapes descend on a Bauhaus grid - tap once to hit the beat, keep the composition in motion.

Anchors

  • Gameplay like: Rhythm Heaven - one tap, one decision per beat, repeated hundreds of times until muscle memory takes over. The tension lives in the gap between reading the pattern and executing it cleanly; a missed tap breaks the chain and the player must choose whether to push harder for the streak or reset to rebuild confidence.
  • Visuals like: The Bauhaus Digital house style - flat 2D canvas with primary-color geometric primitives (circles, triangles, bars) on a visible grid. No gradients, no shadows, no perspective. The grid extends into time: x-axis = position, y-axis = hit zone, vertical scroll = tempo.
  • Sounds like: The foundry's parameterized generative music instrument. A steady pulse track at low volume as metronome bed; descending shapes produce short percussive tones when hit. Off-beat taps produce a muted, dissonant click - audible but not punishing.

Core Loop (first 30 seconds)

  1. See - A primary-colored circle drops from the top of a 5-column grid toward a horizontal hit zone line near the bottom. A continuous pulse track plays at 120 BPM.
  2. Tap - The player presses spacebar (or taps the canvas) when the circle overlaps the hit zone. On the exact beat the shape flashes white and a percussive tone rings.
  3. Repeat - A triangle follows on the next measure, then a bar, then a second circle in blue. Pattern establishes over 16 beats. Misses show as a thin black outline; the track continues unchanged. Three verbs: see, tap, repeat.

Win / Lose

One run: 60-120 seconds (4-8 measures at starting BPM, escalating).

  • Win: 50 consecutive perfect hits. Screen fills with slow yellow grid; pulse track plays resolved chord progression.
  • Lose: 10 misses. Canvas flashes red (200ms), then black rect with white text: "Composition broken. Tap R to rebuild."

Miss counter: 10 red dots at top-right, visible at all times.

Session Shape

  • First 10s: Red circle drops on first beat, no text. Grid lines subtle. Hit zone line near bottom. 120 BPM one-shape-per-beat - any player can tap it. Teaching through situation, not text.
  • First minute: Phase 2: triangles appear alongside circles. Phase 3: hit zone shifts between columns. Phase 4: overlapping shapes on different columns.
  • Replay hook: The streak counter creates persistent pressure - one more try to reach 50 perfects. BPM escalation and precision tightening keep runs fresh.

Difficulty Ramp

  • BPM: 120 → 160 (linear over 8 phases, 10 BPM per phase)
  • Density: Phase 1: one shape per beat. Phase 2: two shapes per beat. Phase 3: two columns required. Phase 4: overlapping shapes.
  • Precision window: ±100ms → ±70ms Good / ±35ms Perfect (tightens 5ms per phase)
  • Economy: Perfect = +100, Good = +50, Miss = −25. Only currency is streak counter — no shop, no upgrades.

Why it's fun (falsifiable hypothesis)

Tension: Control vs. flow. The game sits at the edge of the player's timing ability - simple to learn in 10 seconds, hard to master as BPM climbs. Players negotiate between pushing for perfects (tight window, high risk) and accepting goods (wide window, safe, but streaks require perfects).

CONFIRM if: Players lean into canvas as BPM rises past 140. Streak 30+ shows reduced tap latency (~300ms → ~150ms). Replay rate after loss > 60%.

REFUTE if: Players tap randomly without reading the beat. Replay rate < 30%. Tap latency stays > 400ms after 5 runs.

Scope budget - the OUT list

  • 3D or perspective - only flat 2D canvas
  • Multiple levels or stages - one continuous run, one BPM curve
  • Narrative or story - no characters, no plot
  • Network or multiplayer - single-player only
  • Save/load, user accounts - streaks are per-session
  • Power-ups or item pickups - no collectible shapes
  • Custom music or external audio - generative underscore only
  • Soundtrack selection - one track, one BPM curve
  • Complex combo systems - no chain multiplier, just streak counter
  • Mobile app wrapper or native deployment - browser canvas only
  • Editor or level designer - no user-generated content tools

Test API

The game must expose window.__GAME so the critic can prove the loop works.

State queries (read-only)

  • __GAME.getState() → { bpm, streak, score, misses, phase, isPlaying, isPaused, shapesInPlay, hitZoneColumn }
  • __GAME.getHitAccuracy() → last 50 hits as [ { timing, beatNumber, latencyMs } ]
  • __GAME.isWinConditionMet() → true if streak ≥ 50
  • __GAME.isLoseConditionMet() → true if misses ≥ 10

Simulation hooks (write, for testing)

  • __GAME.simulateHit(beatNumber) → { timing, latencyMs } — tests timing logic without real-time input
  • __GAME.setDifficulty(bpm, densityPhase, precisionMs) — sets config for edge-case testing
  • __GAME.skipToBeat(beatNumber) — jumps to specific beat; pauses game
  • __GAME.setMisses(count) — test lose condition at any point
  • __GAME.setStreak(count) — test win condition triggering
  • __GAME.reset() — full reset
  • __GAME.pause() / __GAME.resume() — pause and resume

Event listeners (for observability)

  • 'game:start' — game begins
  • 'game:pause' / 'game:resume' — pause/resume
  • 'game:win' / 'game:lose' — end-of-run conditions
  • 'game:hit' — every tap: { timing, beatNumber, latencyMs, scoreDelta }
  • 'game:streakChange' — streak changes: { streak, wasPerfect }

window.__GAME object available from __GAME.init() — promise resolves when canvas and audio context are ready.
